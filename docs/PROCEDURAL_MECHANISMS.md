# Procedural CVT mechanisms

This increment follows the run-reference reuse fix at `7b10f06`. It replaces the
illustrative lines and floating followers with connected procedural mechanisms.
The assembly uses the mounting choices agreed with Kai on October 5, 2026 (UTC).

## Mounting and motion

| Part | Attachment | Relative motion |
| --- | --- | --- |
| Primary flyweight carrier and pivots | Fixed sheave / shaft | Shaft rotation only |
| Flyweights and their rollers | Fixed carrier pivots | CINDER's resolved roller motion |
| Primary solid ramps and supports | Movable sheave | Axial translation |
| Three primary guide rollers | Central shaft | Shaft rotation only |
| Three straight axial guide slots | Movable hub surrounding the shaft | Axial translation without relative twist |
| Three secondary helical slots | Fixed sheave / shaft | Shaft rotation only |
| Secondary roller pins and rollers | Movable hub | Axial translation and CINDER's relative helix rotation |

The primary guide is the 90-degree limiting geometry in the paper's convention;
it is drawn as a straight slot, without introducing a torque-reactive helix into
the primary's physics. Primary flyweight count comes from the assembly. Both
torque-transfer mechanisms use three stations.

The primary spring sits between a shaft-supported seat and a movable-hub seat;
it compresses as the primary closes. The fixed spring seat connects through the
guide pins outside the moving sleeve. The secondary spring compresses and winds
as its movable sheave opens. Its seats connect to the fixed cam support and the
moving hub. Open supports make these connections visible.

## Geometry and ownership

- CINDER continues to own the mechanics. The API projects roller coordinates,
  ramp contact side, secondary axial position and relative rotation, and spring
  presence. Frontend API types are generated by the existing contract pipeline.
- The secondary seating transition is an explicit pose sample. Interpolation
  must not move the secondary early during the primary deadzone.
- Both the primary pivot frame and ramp reference frame receive the same axial
  packaging offset, preserving contact. Ramps are children of the movable sheave.
- Ramps have solid backing and supports attached at the sheave's back surface.
  Helix slots are holes in an annular wall, with radial rollers on the other hub.
- Slot surfaces are generated around the resolved follower path. Panel seams
  follow that path, so a track can cross a 120-degree sector without being cut
  off. Illustrative roller size reduces when needed to separate steep tracks.
- Bracket dimensions, roller widths, spring coil dimensions and weight outlines
  are schematic. They are not recovered CAD dimensions or manufacturing designs.
  They do not change the simulated masses, inertias, stiffnesses or forces.
- Shared scene materials and main visual dimensions live in `sceneAppearance`.
  Mesh primitives, slotted sleeves, batching and springs are in
  `mechanismGeometry.ts`; attachment and motion are in `mechanisms.ts`.

Rigid hardware is batched by material. Springs deform reusable buffers and skip
updates when their pose has not changed. The landing page retains its demand-only
rendering and orbit-only interaction. Transparent playback makes the enclosing
sheaves and cam wall translucent while retaining opaque working parts. Camera
bounds include the outboard mechanisms.

## Verification

Temporary acceptance checks (not a new test suite) covered:

- 129 shift positions from zero to maximum travel for the McMaster default and
  a separate 5-degree helix, which traverses more than one sector.
- Actual parent attachments, axial motion, roller-to-ramp distance, ray-cast slot
  flanks, spring coil spacing, camera bounds and reusable geometry buffers.
- Default ramp contact discrepancy below 0.001 mm and secondary axial sampling
  discrepancy below 0.001 mm. Small slot clearance absorbs tessellation error.
- Landing orbit, anonymous demo playback, transparency, orthographic view, blur,
  section view, route disposal/re-entry and desktop/mobile layout in Chromium.
- No GLB/CAD/decoder downloads and no browser page errors.
- Generated contracts, TypeScript build, production bundle and changed frontend
  file lint. Backend formatting and lint pass apart from six existing TRY004
  findings in unchanged gateway validation helpers; those are left unchanged.

These checks verify the schematic renderer, not a manufacturing collision study
or a hardware GPU performance benchmark. No solver, simulation evidence, database
migration, CI workflow or committed unit-test suite changes are included.

## Applying and running

Apply the patch after the run-reference reuse patch. Restart the API and frontend.
No database wipe or migration is needed. `npm run dev` and `npm run build` regenerate
frontend contracts through the existing scripts. Updated compact landing and
demo scenes are included. If changing the preset later, regenerate them from
`backend` with `venv/bin/python -m app.scripts.build_scenes` (or the equivalent
activated virtual environment command on Windows).
